Why this matters

Coupling: how tightly parts are tied together

Whenever one part of the code relies on another, a change in one can ripple into the other. Some of this is normal and necessary.

Parts that many others rely on are risky to change, because a mistake spreads to everything that uses them. Parts that rely on many others break easily, because any of those can change under them. Fewer connections, all pointing the same way, make code cheaper to change, test and hand over.

Cycles: parts that depend on each other in a loop

A cycle is a loop: A relies on B, and B, directly or through others, relies back on A. These parts all depend on each other, so none of them can be changed, tested or reused alone.

Work on any part of a loop tends to drag in all of it, and a bug in one part can surface in all of them. Breaking a loop is usually the first thing worth fixing, because it makes every part in it easier to work with.
